# 接口文档分析方法

## 从接口文档提取测试点

| 文档元素 | 提取动作 |
|---|---|
| 每个写接口(POST/PUT/PATCH) | 1 个功能点;必配 幂等重放用例 + 失败零副作用用例 |
| 错误码表 | **每个错误码至少 1 条触发用例**;码+HTTP状态+触发条件三者对上 |
| 必填字段表 | 缺每个必填字段各 1 条(不得用默认值静默成功) |
| 枚举字段 | 非法枚举值 1 条 + 大小写变体(文档说不区分时) |
| 分页约定(limit/cursor/page) | 越界值(0/101/abc)、翻页不重不漏 |
| 版本字段(expectedVersion 等) | 旧版本冲突用例;**expectedVersion 的真实来源字段要实测确认** |
| 权限标注(需xx角色) | 每种角色×接口的 允许/拒绝 矩阵 |

## 实测优先原则

文档与实现不一致时(实测 3 次以上稳定复现):
1. 断言按**实测行为**写
2. 差异记录为「文档差异」条目(不是用例失败)
3. 不确定的间歇行为 → xfail 记录,不猜

## 常见契约陷阱(踩过的)

| 陷阱 | 处理 |
|---|---|
| 配置写命令要包 `configuration:{...}` 而文档示例平铺 | 按实测请求体写 |
| expectedVersion 用 poolVersion 而非 configVersion | 版本字段逐一实测哪个能写成功 |
| 幂等键必须 UUID 格式 | 非 UUID → 400 是独立用例 |
| 错误结构 {error:{code,message}} | 断言 code 而非 message(message 不稳定) |
| 越权返回 404 而非 403 | 不泄露存在性;按实测断言并注明设计意图 |

## 接口测试点 → 9 维度映射速查

- 正向:合法请求+完整响应字段核对(字段逐一断言,不只 status)
- 边界:参数极值/精度/类型错乱("abc"/1e5/负数)
- 异常:每个错误码触发 + 零副作用
- 并发:同幂等键并发/不同键抢余额
- 权限:角色矩阵+跨用户+伪造身份字段
- 一致性:接口值 vs 账本/列表 vs 详情
- 配置联动:改配置→接口返回值变化→还原
- 状态机:状态枚举的非法跳变/终态操作
- 安全:错误信息不泄露 schema、响应不含他人数据
