# 测试点维度清单(9+4 维)

功能点依次过 9 个功能维度;整个产品层面再过 3 个非功能维度 + 1 个横切矩阵
(依据 ISO 25010 质量模型与 HTSM 裁剪,只保留对用例设计有直接产出的部分)。
**不是每维都有产出**——没有依据时:优先用「测试预言」显式推导(见文末),
推导不出才记悬置项,不为了凑数而编造预期。

## 维度 1:正向功能
- 用合法输入走通全流程,用户**看到什么**(不是接口 200,而是页面上/结果里的可感知变化)
- 空态(新用户/无数据)也是正向:必须是空列表/引导文案,而不是报错
- 多语言/多市场等并列分支各走一条

## 维度 2:输入边界
- 长度/数量:等价值**两侧各取一点**(3 合法→2 非法;32 合法→33 非法)
- 精度:合法精度上限 + 超精度各一点;**科学计数法(1e5)、千分位(1,000)、前导/尾随空格、纯空格、空串**
- 数值:0 / 负数 / 超上限 / 恰好等于上限 / 恰好等于下限(等值是独立用例,见维度8)
- 大小写:大小写不敏感的(地址/名称)三种混排各一条
- 超长输入(256+字符)不崩溃、布局不撑破

## 维度 3:异常容错
- 每条都要断言三件事:**明确错误码/文案** + **不静默成功** + **零副作用**(不扣款/无脏数据/无记录)
- 失败后重试路径:保留用户输入可重试;**禁止系统自动改方向/金额/降级业务类型**
- 网络/接口失败:错误提示 + 不白屏 + 恢复后可重试
- 相等边界属此维:**收盘恰好等于门槛=失败,无平局无退本金**(判定类)

## 维度 4:并发幂等
- 同幂等键/同请求连点两次 → 同一结果、只生效一次、只扣一次款
- 并发多请求抢同一资源(同余额/同名额)→ 不得透支/超发
- 会话失效后按原幂等键查询 → 不重复扣款

## 维度 5:权限隔离
- 无权角色调写接口 → 拒绝,**且数据真的没变**(不只看状态码)
- 跨用户读他人资源 → 404 不泄露存在性(订单/提现/记录三维)
- 伪造角色头/请求体里的 adminId/uid → 服务端忽略,审计归属真实身份
- 自我保护:不能停用自己/移除自身角色/自审自己提交的单(**用缺字段探测验证,不真执行**)
- 校验与鉴权顺序:无权用户发非法请求体,应 403 而非 400(否则泄露 schema)

## 维度 6:数据一致性
- 守恒不变式:余额变化 == 全部分录 delta 之和;总量只在明确业务点增减
- 扣款恒等:总扣款 == 本金 + 费用 + 保险费(逐笔,不重复计费)
- 双处展示同一数据(列表 vs 详情 vs 汇总)必须一致
- 冻结类:进行中=未结算之和;全部终态后归零
- 分页:翻页不重不漏;插入新数据后已翻页不重复出现

## 维度 7:配置联动
- 后台改配置(费率/门槛/比例/开关) → **前台数据和行为真的变** → 还原后恢复
- 写法:读快照 → 改一个字段 → 断言前台变化 → finally 强制还原 → 断言恢复;
  **快照落盘防进程被杀**
- 跨配置一致性:两项配置可能冲突时(如池限额 vs 策略金额),保存必须互相校验
- 版本号用哪个字段(expectedVersion 的真实来源)实测确认,不猜

## 维度 8:状态机
- 列出状态枚举(从接口响应/文档收集),每条**合法转移**一条正向用例
- 每条**非法跳变**一条负向(终态后再操作/跳过中间态/重复终态操作)
- 回退/取消/过期路径:数据恢复到哪个态、已产生的影响(分录/次数/进度)如何处理
- 边界时刻:恰好到期/恰好开场 的请求归哪边

## 维度 9:安全
- XSS:特殊字符(<script>、'、--)输入后转义,不执行不破版
- 信息泄露:错误信息不暴露字段名/schema(对无权用户)、404 不泄露资源存在性
- 越权数据:响应中不包含他人数据;列表接口默认隔离
- 幂等键/nonce 重放:一次性凭据第二次使用必须拒绝

## 维度 10-12:非功能三维(产品级过一遍,不是每功能点过)

### 维度 10:性能效率(P2 为主,超时类 P1)
- 关键操作响应时间有无承诺?无承诺 → 悬置问用户目标值(不猜具体毫秒)
- 并发量:产品声称支持多少用户/TPS?→ 并发用例的目标值来源
- 大数据量:列表 1 万条/万级记录时翻页与加载(与"仅展示前1万条"类声明对齐)
- 资源:轮询/推送频率(原型若有轮询秒数,1s 轮询本身就是测试点)

### 维度 11:兼容与可靠(P1/P2)
- 兼容:多端(响应式断点)/多语言(文案长度撑破布局、RTL)/多网络(弱网超时行为)
- 可靠:故障恢复(断网重连/接口5xx后重试,**不重复执行已提交业务**)
- 降级:外部依赖不可用时页面给什么(空态/错误/缓存)——与外部依赖清单联动

### 维度 12:易用性与体验(P2,走查式)
- 空态有引导而非空白;加载有反馈;危险操作有确认
- 错误文案用户能懂(说"余额不足差 X"而非堆错误码)
- 此维多为走查记录,不强制成 xlsx 用例行

### 维度 13(横切):CRUD × 权限实体矩阵
对每个**数据实体**(订单/代币/证书/配置...)建矩阵,行=角色,列=Create/Read/Update/Delete:

| 实体 | 角色 | C | R | U | D | 依据 |
|---|---|---|---|---|---|---|
| 分配计划 | Owner | ✅ | ✅ | ✅(未发布时) | ✅? | 🔶删除能力PRD未写→悬置 |
| 分配计划 | 协作者 | ❌ | ✅ | ❌ | ❌ | |

每个 ❌ = 1 条越权用例;每个 ✅ = 正向用例;**矩阵里的 ? = 悬置项**。
此矩阵同时是权限维度(5)的系统化展开,避免漏角色×实体组合。

## 测试预言(Oracle,与铁律0配合)

**铁律0说"不猜"——但 Oracle 不是猜**:它是显式声明的判断依据,
用 Oracle 推导的预期必须**在备注列标注 Oracle 类型**(区别于 ✅直接依据)。
按 FEW HICCUPPS 裁剪,允许的 Oracle:

| Oracle | 问句 | 备注标法 |
|---|---|---|
| 一致性 | 同类功能/同产品别处怎么表现?此处应与之一致 | Oracle:内部一致 |
| 历史 | 上一版本/上一轮这里是多少?不应无故变化 | Oracle:历史基线 |
| 声明 | PRD/原型/客服话术**声称**什么?行为应兑现声明 | Oracle:产品声明 |
| 可解释性 | 操作与结果能讲出因果吗?讲不出=可疑 | Oracle:因果 |
| 法规/惯例 | 行业通行做法(如金额两位小数) | Oracle:行业惯例 |
**推导链只能用一层**:Oracle 推出的预期若再叠推测,即为违规,回悬置。

## 实战教训(违反必返工)

| 教训 | 来源 |
|---|---|
| 判定不等号方向写错(> vs >=)= 白送钱,必须明确写"严格大于/恰好相等=失败" | 结算边界 |
| 并发下单导致余额为负是最高优先级缺陷,并发用例不可省 | 资金系统 |
| 池/市场选择不能"取第一个",列表顺序不定;文档基线值(如赠送额)只作 WARN | 环境漂移 |
| 破坏性测试(停用超管)曾锁死共享环境,只能探测式验证 | 事故教训 |
| 行为与文档不符时:断言按**实测契约**写,差异记录为缺陷/文档问题,不硬套文档 | 版本漂移 |
| 外部依赖(行情源/第三方)要单独识别——实测曾发现行情与币安不可对账(D11),这类问题功能测试全绿也发现不了 | 外部依赖 |
